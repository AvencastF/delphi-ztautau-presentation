# DELPHI Z → ττ presentations

Independent Slidev decks about measuring the full tau-pair spin density matrix in archived DELPHI LEP data ($e^+e^- \to Z/\gamma^* \to \tau^+\tau^-$, 1992–1995), with one shared dependency installation and reusable infrastructure.

For agents: read [AGENTS.md](AGENTS.md). For step-by-step creation, shared-component recipes, asset paths, and anti-duplication rules, read the [authoring guide](docs/authoring.md). The [shared directory guide](shared/README.md) explains ownership at a glance.

Published site: <https://avencastf.github.io/delphi-ztautau-presentation/> (landing page), with each deck at `https://avencastf.github.io/delphi-ztautau-presentation/<deck>/`.

## Getting started

Run commands from the repository root using a current Node.js LTS release.

```bash
npm ci
npm run dev -- ztautau-status-1994-20261022
npm run build -- ztautau-status-1994-20261022
npm run export -- ztautau-status-1994-20261022
```

The preview opens at http://localhost:3030. Edit the selected deck's `slides.md` and `slides/` files. Development retains `--open --remote`; remote mode exposes the preview to your network.

Extra arguments are forwarded to Slidev:

```bash
npm run dev -- ztautau-status-1994-20261022 --port 3031
npm run build -- ztautau-status-1994-20261022 --base /delphi-ztautau-presentation/ztautau-status-1994-20261022/
```

Run Slidev through these scripts rather than `npx slidev` inside a deck: the launcher removes the `VSCODE_CWD` variable that Cursor/VS Code terminals export, which otherwise makes UnoCSS's icon preset skip its loader and silently drop every `i-*` icon from dev and build output.

A single-deck build writes to `<deck>/dist/`. Export retains `--with-clicks --per-slide --wait-until none` and requires Playwright's Chromium browser. If needed after installing dependencies, run `npx playwright install chromium`.

## Create a presentation

```bash
npm run new -- My_Talk
npm run dev -- My_Talk
```

This creates a starter `slides.md` (default theme plus the `slidev-addon-ztautau` addon) and a `style.ts` with the shared stylesheet imports. Do not run it on an existing deck name. Names may contain letters, numbers, underscores, and hyphens, and must begin with a letter or number. The names `site`, `node_modules`, `shared`, `tools`, `gh-pages`, `output`, and `docs` are reserved.

No per-deck package manifest, lockfile, dependency installation, workflow, or copied component library is needed. Add the talk's own content, assets, `SOURCES.md` (provenance of every number shown), and `README.md`. Add a landing-page entry manually when you want the talk listed there; the generator does not change the landing page.

## Structure and customization

```text
package.json / package-lock.json     One dependency set; workspace shared/slidev-addon-ztautau
tools/                               Development, build, export, build:all and scaffolding commands, tests
shared/slidev-addon-ztautau/         LaTeX, ZoomablePlot, ChapterRail; useStepMotion, tex; page-number layer; UnoCSS and Vite config
shared/styles/                       Shared CSS: base, Graphite & Gold theme, chapter rail, status-report layouts
shared/brand/                        Bundled DM Sans font (OFL), so decks work offline
gh-pages/                            Landing page (index.html and assets), copied into site/ by build:all
<deck>/slides.md                     Deck headmatter and the ordered src: list
<deck>/slides/                       Presentation-specific content
<deck>/public/                       Presentation-specific assets and existing URLs
<deck>/components/                   Unique components and local component overrides
<deck>/data/                         Talk datasets and slide/figure generators
<deck>/SOURCES.md, README.md         Provenance of every number; owner decisions, rules and caveats
site/                                Generated by build:all; ignored
```

Each deck keeps Slidev's default theme and opts into `slidev-addon-ztautau` in its headmatter. npm links the local addon workspace automatically. No manual symlinks or package publishing are needed.

The imports in `style.ts` preserve CSS order and pass every shared file through UnoCSS's directive transformer:

```ts
import '../shared/brand/fonts.css'
import '../shared/styles/main.css'
import '../shared/styles/animations.css'
import '../shared/styles/base.css'
import '../shared/styles/graphite.css'
import '../shared/styles/chapters.css'
import '../shared/styles/status.css'
// deck-local ./styles/*.css imports follow
```

Use JavaScript/TypeScript imports here rather than CSS `@import`, which would leave shared `--uno` directives unexpanded.

Shared infrastructure changes affect all decks: build and review every presentation before accepting them. Keep talk content, data, and provenance local. Deck-local components override shared components of the same name. Global layers are additive: a local global layer does not replace the addon's page number. Deck-local UnoCSS config should contain only additional safelist entries, such as icons used by dynamic markup.

## Complete website and CI

```bash
npm test
npm run build:all
npm run build:all -- --base /delphi-ztautau-presentation/
```

`build:all` recreates the generated `site/` directory and sequentially builds every top-level folder containing `slides.md` into `site/<deck>/`, with base `/<repository>/<deck>/`. The default repository name is `delphi-ztautau-presentation`; `--base` overrides the prefix. The `gh-pages/` landing tree is then copied into `site/`. Treat `site/` as disposable; keep source files and exports elsewhere.

GitHub Actions runs one root `npm ci`, builds every deck, and publishes the complete `site/` to GitHub Pages. There are no per-deck installs or workflows.

## Listing a talk on the landing page

The generator and `build:all` never rewrite `gh-pages/`. To list a deck, add an entry for it to the `talks` array in `gh-pages/index.html`, following the format of the existing entries. Use a relative link such as `./<deck>/` so it keeps working under the Pages sub-path. A deck is built and published even when no landing entry points to it. Listing a talk publicly requires the user's authorization.
