## Presentation rules applied (owner review of 2026-10-23)

Body text ≤ 70 words per slide (table cells, figure captions, key-value entries and tags excluded; checked with `python3 data/wordcount.py 70`, report in `data/wordcount-report.txt`: no main-deck slide above 70, most between 10 and 50), subtitles ≤ 20 words, one short "Source:" footer per slide in plain words, bare identifiers as italic tags, ≤ 7 rows × 4 columns in main-deck tables (appendix tables are denser), 2×2 figure grids with χ²/dof badges (green ≤ 1.5, amber ≤ 3, red > 3 per dof), callouts (ok / warn / decision / open) ≤ 15 words, semantic tags (data, simulation, selection, ML, decision, open) with a legend on the chain slide. Removed prose lives in the presenter notes.

## Writing rules applied (owner instruction of 2026-10-23)

No internal shorthand on the slides (owner instruction of 2026-10-23): every region, cut, variable, campaign, run, model version and directory is described in plain words in the slide body, with the identifier as a small italic note (`<span class="id">…</span>`). Raw identifiers live in `SOURCES.md`. Repository references are hyperlinked: the simulation and converter repositories are public and link to the exact branch / revision and files; `AvencastF/delphi-ztautau-ana` and `UW-EPE-ML/EveNet-Align` answered "not found" to an anonymous request on 2026-10-23 (private or not yet pushed), so their links point at the repository root and the slide footers say so.

## Caveats baked into the slides

- Conversion success is not detector validation.
- ML numbers are MC closure on held-out validation rows (no independent test part); v5 equals v2 within statistics, better than v3/v4 except π-leg resolution in ππ (0.75° vs 0.61°).
- The classifier evaluation on record (2026-10-15) is for an epoch-27 checkpoint with `mc_split: all`, not the frozen epoch-29 classifier.
- The 2026-10-22 decision to retrain the classifier on the shared v5 conversion is pending.
